# MCP del Organizador — OAuth 2.1 AS propio, tokens per-usuario scoped a membresía

## Contexto

Renacimiento del MCP tras el retiro del god-mode (ADR-0023), con el modelo invertido: cada
[[Organizador]] conecta su cliente de IA (Claude Code, Claude Desktop, etc.) al **MCP remoto de la
Plataforma** y opera SU cuenta por chat — configurar sus Tiendas, productos, sorteo, el Borrador de
su página, conectar Flow (write-only) y crear otra Tienda. La autorización de cada llamada sale de
la `TenantMembership` viva, no de un secreto de entorno. El patrón completo es **espejo del MCP de
terranova_ADMIN** (su ADR-0009; mismo stack, en producción — instrucción del usuario: "lo quiero
justamente así"), adaptado al dominio: identidad `User.id`, selección de tienda por argumento
autorizada por membresía, y matriz de límites sensibles propia. El MCP de administración de
plataforma queda FUERA (diferido con el superadmin, ADR-0023).

## Decisiones

- D1: **OAuth 2.1 con AS propio** (Authorization Code + PKCE S256 + DCR RFC 7591), no PAT ni
  delegación a Google. Razón: decisión del usuario en Q1 con referencia obligada a terranova_ADMIN;
  DCR hace que `claude mcp add` funcione solo; revocación granular per-cliente; consent brandeado.
  Ver [ADR-0025](../docs/adr/0025-mcp-organizador-oauth-as-propio.md).
- D2: **Tokens opacos hasheados SHA-256, identidad = `User.id`**, access 1 h + refresh 30 d (TTLs
  en código). Razón: un token propio solo se compara ⇒ hash irrecuperable (a diferencia de
  [[CredencialFlow]], cifrada porque se usa); User es fila real de NextAuth (terranova usaba email
  Cognito). El token plano se muestra UNA vez (respuesta del token endpoint).
- D3: **El MCP vive en el apex, un solo endpoint, un solo modo (`organizador`)**. Razón: el token es
  per-usuario y cruza tiendas — "crear otra Tienda" no puede colgar del host de una; el modo
  admin/plataforma está diferido (ADR-0023) y no se deja ni endpoint vacío.
- D4: **Selecciona-jamás-autoriza**: toda tool que opera una Tienda recibe el slug como argumento y
  `resolverTenantAutorizado` autoriza contra la membresía viva en CADA llamada. Razón: espejo de
  ADR-0022; es exactamente lo contrario del `storeSlug` god-mode retirado (ADR-0023).
- D5: **El MCP es un borde**: sus tools invocan los mismos use cases de `src/server/domain/` que el
  panel, reconstruyendo el `acceso` desde la identidad del token (patrón sesión sintética de
  terranova). Razón: cero duplicación de lógica; los guards del dominio (fail-closed, Decimal,
  $transaction) aplican gratis.
- D6: **Transporte `@modelcontextprotocol/sdk` (`StreamableHTTPServerTransport` stateless) en pages
  router**; la dep huérfana `mcp-handler` se **desinstala**. Razón: terranova lo prueba en
  producción sin app router; elimina el último resto del approach viejo.
- D7: **Matriz de tools v1** aprobada por el usuario en Q2: SÍ configuración/productos/sorteo
  (crear-editar)/checkout fields/Borrador de página/crear Tienda/lecturas (incl. ventas y
  participaciones — es SU data, misma membresía que el panel). NO publicar (tienda ni página,
  ADR-0018: checkpoint humano contra editores automáticos — el MCP ES uno), NO ejecutar sorteo
  (irreversible, ADR-0008), NO borrar, NO leer secretos Flow.
- D8: **Flow write-only vía MCP** (excepción empujada por el usuario en Q2): `guardarCredencialFlow`
  reusa el use case del panel (cifrado at-rest ADR-0006, jamás devuelve/loguea el secreto) + tool de
  estado sin secretos (Configurada/no, ambiente, fecha). Razón: ADR-0006 protege que la PLATAFORMA
  no exponga secretos; write-only no los expone. **Riesgo residual documentado**: el secreto viaja
  por el contexto del LLM y queda en el historial DEL usuario — la description del tool lo advierte
  y recomienda el panel como camino preferente.
- D9: **Redirect URIs de DCR: loopback + allowlist exact-match de callbacks HTTPS de clientes
  conocidos** (p. ej. el callback de claude.ai para Claude Desktop/web). Razón: terranova es
  loopback-only (Claude Code), pero los Organizadores no-técnicos usan Claude Desktop/web; el
  registro no otorga nada sin consentimiento de un usuario logueado. REVISABLE en implementación
  (la allowlist exacta).
- D10: **Scope único `mcp`** en v1; la matriz de límites vive en el registro de tools (lo que no
  existe no se puede llamar). Scopes finos = puerta abierta.
- D11: **Auditoría `McpAuditLog` append-only** (tool/result/errorCode/args sanitizados, SIN FK para
  preservar historial). Razón: trazar qué hizo el agente; espejo terranova.
- D12: **Vocabulario nuevo en CONTEXT.md**: [[MCP del Organizador]], [[Conexión MCP]], [[Token
  MCP]] definidos; [[Editor MCP (RETIRADO)]] actualizado para apuntar al sucesor. ADR-0025 creado
  (nivel 2: borde nuevo de auth de la plataforma).

## Plan

1. **Schema** (`prisma/schema.prisma`): portar los 5 modelos de terranova adaptando `userEmail` →
   `userId` (String; FK vs String puro lo decide schema-guardian — audit SIEMPRE sin FK). Índices y
   `onDelete: Cascade` de codes/tokens hacia `McpClient(clientId)`. `db push`. (F01)
2. **AS OAuth** (`src/pages/api/mcp/oauth/{register,authorize,authorize/decision,token,revoke}.ts` +
   `src/pages/api/well-known/*` + rewrites en `next.config.js` + `src/pages/mcp-consent.tsx` en el
   apex): portar el dance completo de terranova (PKCE S256 obligatorio, auth code single-use
   atómico, DCR con validación D9, WWW-Authenticate RFC 6750). `/authorize` exige sesión NextAuth
   (login del apex, ADR-0019). (F02)
3. **Transporte** (`src/server/mcp/createMcpHandler.ts` + `src/pages/api/mcp/handler.ts`): validar
   bearer → `tokenHash` → `userId` → cargar membresías canónicas (`cargarMembresiasCanonicas`) →
   contexto MCP con `acceso` sintético; `McpServer` + `StreamableHTTPServerTransport` stateless.
   Desinstalar `mcp-handler` de package.json. (F03)
4. **Tools de lectura** (`src/server/mcp/tools/`): mis tiendas (membresía), estado + checklist de
   publicación, ventas y participaciones del sorteo, estado Flow SIN secretos, outline/catálogo de
   página (reusa `catalogoDelEditor.ts`). (F04)
5. **Tools de configuración**: guardarConfiguracionTienda + CRUD de campos de checkout, vía use
   cases existentes con tenant autorizado por D4. (F05)
6. **Tools de productos y sorteo**: productos crear/editar/activar/desactivar (precio como string
   decimal validado server-side, sin binarios), sorteo crear/editar (fechas/premio/textos). (F06)
7. **Tools de página**: operaciones sobre el Borrador (agregar/editar/reordenar/quitar secciones,
   tema) sobre los use cases del editor visual; el humano previsualiza y publica desde el panel. (F07)
8. **Tools de cuenta**: crear Tienda (use case `crearTienda`) + `guardarCredencialFlow` write-only
   con advertencia D8 en la description. (F08)
9. **Panel "Conexiones IA"** en Configuración (Mantine, patrón `McpConnectionsSection` de
   terranova): listar conexiones con último uso, revocar token/conexión. (F09)
10. **Audit**: wrapper de invocación que registra en `McpAuditLog` con args sanitizados (jamás
    secretos ni PII extensa). (F10)

## Invariantes

- I1: **Membresía autoriza en cada llamada** — el slug/tenantId de una tool selecciona, JAMÁS
  autoriza (`resolverTenantAutorizado`); scoping por `tenantId` en toda query (ADR-0005/0022/0024).
- I2: **Ningún tool devuelve secretos**: credenciales Flow en ninguna forma; tokens solo hash en DB,
  plano una sola vez en el token endpoint.
- I3: **No existen** tools de publicar (tienda/página), ejecutar sorteo, borrar, ni leer
  credenciales. El registro de tools ES la whitelist.
- I4: **Cero lógica de dominio en el borde MCP** — todo pasa por use cases de `src/server/domain/`.
- I5: PKCE S256 obligatorio; auth code single-use atómico; redirect URIs exact-match (loopback +
  allowlist D9); tokens con expiración y `revokedAt` chequeados en cada validación.
- I6: Dinero `Decimal` server-side (precios vía tool con la misma validación del panel); operaciones
  compuestas en `$transaction`.
- I7: `McpAuditLog` append-only, args sanitizados, sin FK.
- I8: El AS no reemplaza NextAuth: `/authorize` exige la sesión Google existente; sin sesión no hay
  consentimiento ni token.

## Out of scope

- MCP de administración de plataforma / superadmin (diferido, ADR-0023).
- Scopes OAuth finos por capacidad (scope único `mcp`, D10).
- Subida de binarios (PDF de producto, imágenes de marca) vía MCP.
- Publicar, ejecutar sorteo, borrar, leer credenciales (límites D7 — no son deuda, son diseño).
- Cierre de `STOREFRONT_PREVIEW_TOKEN` (deuda de ADR-0023, carril propio).
- Cache in-memory de tokens (válvula futura si el lookup por request duele).
- Rate limiting del AS/MCP (anotar como pendiente de hardening pre-F10 go-live).
